Putting an app in the cloud does not remove the possibility of failure

Cloud platforms can make computing flexible, but a service still depends on networks, identity systems, regions and operational decisions.

BY Civora Research DeskPUBLISHED 2026-11-10
TechnologyBehind the CloudC·

'It's in the cloud' can sound like a guarantee that an application will always be available. The phrase describes a model of delivering computing resources, not a promise that every underlying machine, network or software component is immune to problems.

NIST defines cloud computing as on-demand access to shared configurable resources. Companies can scale servers and storage without owning every piece of physical infrastructure. That flexibility can improve operations, but it also creates dependencies on external providers.

An outage may begin in networking, storage, software configuration or authentication. Even when the application code itself is healthy, a broken dependency can prevent users from logging in or loading their data.

Redundancy helps only when it addresses the actual failure mode. A service that runs on multiple servers in one region may still struggle during a region-wide incident. Backups help recovery but are different from uninterrupted availability.

Providers and customers share responsibilities in ways that depend on the service model. Some reliability choices belong to the cloud provider; others remain with the organization building the app.

The useful question is how a system fails, not whether someone described it as cloud-native. A good service should explain what users experience during an outage and how important information is protected or restored.

Reporting note: Civora reviewed NIST cloud definitions and resilience guidance. We did not investigate a specific cloud-service outage.
